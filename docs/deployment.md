# Развертывание на сервере

## Требования

- Linux-сервер с Docker Engine и плагином Docker Compose;
- домен, A/AAAA-запись которого указывает на сервер;
- доступные извне TCP-порты 80 и 443;
- диск для PostgreSQL, загруженных файлов и резервных копий.

Клонируйте репозиторий. Создайте `.env` из `.env.example` и задайте `POSTGRES_PASSWORD`, `SESSION_SECRET` (случайное значение от 32 символов), `DOMAIN`. Не используйте пробелы и символы URL-разделителей в пароле PostgreSQL: он включается в строку подключения. `APP_PORT` задаёт только локальный порт для администратора сервера; внешний доступ идёт через Caddy. Файл `.env` не коммитьте и ограничьте права доступа к нему (`chmod 600 .env`).

```sh
docker compose -f docker-compose.yml -f compose.production.yml up --build -d --wait
docker compose -f docker-compose.yml -f compose.production.yml ps
curl -fsS "https://$DOMAIN/api/health"
```

На первом запуске схема БД применяется автоматически. Эндпоинт health должен вернуть `ok: true`, `dbReady: true`, `mode: postgresql`. Caddy получает TLS-сертификат автоматически после настройки DNS и открытия портов. Проверка Caddy с фиктивным доменом не заменяет проверку сертификата на рабочем сервере.

Создайте первого администратора только на пустой БД. Пароль передавайте через stdin и не включайте в историю команд:

```sh
read -rsp 'Initial admin password: ' ADMIN_PASS; echo
printf '%s' "$ADMIN_PASS" | docker compose -f docker-compose.yml -f compose.production.yml exec -T app bun db/bootstrap-admin.ts admin@example.org 'Administrator Name'
unset ADMIN_PASS
```

После входа создайте факультет, кафедру, группу, преподавателя и студента; назначьте преподавателя на группу. Проверьте полный цикл сдачи на тестовых учётных записях, затем отключите тестовых пользователей до ввода реальных данных.

Пользователь может сменить начальный пароль через кнопку «Сменить пароль»; после смены все старые сессии закрываются. Если пароль забыт, администратор сервера с доступом к Docker может сбросить его через `db/reset-password.ts`: передайте email аргументом, новый пароль через stdin и установите `ALLOW_PASSWORD_RESET=true` только для этого запуска. Сброс также закрывает все сессии пользователя.

Обновление: сначала сделайте резервную копию, затем `git pull` и `docker compose -f docker-compose.yml -f compose.production.yml up --build -d --wait`. Миграции запускаются при старте приложения. Перед обновлением, меняющим схему, проверьте восстановление копии на отдельном сервере или проекте Compose.
