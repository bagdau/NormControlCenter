# НормКонтрольЦентр

Локальное демо сдачи учебной работы: студент отправляет PDF/DOCX или документ из формы, получает квитанцию, преподаватель публикует замечания, студент пересдаёт новую версию, преподаватель фиксирует внутреннее согласование. Официальные оценки, ЭЦП, LMS и реальные данные в проект не входят.

## Проверенный запуск с PostgreSQL

Нужен Docker Desktop. Скопируйте `.env.example` в `.env`, задайте случайные `POSTGRES_PASSWORD` и `SESSION_SECRET` (не менее 32 символов), при необходимости установите `APP_PORT=3001`.

```powershell
docker compose up --build -d
docker compose exec -T app bun db/seed.ts
docker compose ps
```

Откройте `http://localhost:3001`, если `APP_PORT=3001`, иначе `http://localhost:3000`. PostgreSQL не публикует порт, HTTP приложения привязан только к `127.0.0.1`. Seed содержит **только вымышленные данные** и запускается вручную. Повторный seed идемпотентен. `docker compose down` останавливает сервисы и сохраняет тома; не используйте `down -v`, если хотите сохранить данные.

Синтетические роли: `smailov@normocontrol.local` (студент), `omarova@normocontrol.local` (преподаватель), `admin@normocontrol.local` (администратор). Пароль локального seed: `DemoNormo2024!`. Быстрые кнопки входа доступны только в `DEMO_MODE=true` без БД. На PostgreSQL вводите email и пароль вручную.

## Локальная проверка

```powershell
npx --yes bun install --frozen-lockfile
npx --yes bun run lint
npx --yes bun test
npx --yes bun run build
$env:SMOKE_BASE_URL='http://localhost:3001'; node tests/postgres-smoke.mjs
```

Последняя команда требует запущенный Compose с seed и добавляет только синтетические задания и работы. Сценарий проверяет v1 → замечание → возврат → v2 → согласование, скачивание байтов по хешу квитанции и одновременную сдачу с одним ключом. Для проверки после перезапуска передайте `SMOKE_VERIFY_SUBMISSION_ID` из вывода основной проверки.

## Быстрое демо без БД

```powershell
npx --yes bun run dev
```

Откройте `http://localhost:3000`. На экране виден баннер о хранении в памяти. Данные исчезают при перезапуске и этот режим не доказывает работу PostgreSQL. Сначала войдите студентом, сдайте лабораторную из формы и откройте квитанцию; затем войдите преподавателем и откройте PDF из очереди.

## Важные границы

Это локальный демонстрационный срез, **не готовый пилот**. Текущая авторизация использует bearer token в памяти браузера, а не HttpOnly cookie; отсутствуют ограничение попыток входа, серверное сохранение черновиков и проверенное восстановление из резервной копии. Синтетические записи импорта без сохранённых байтов файла возвращают ошибку скачивания вместо вымышленного PDF. Для DOCX есть скачивание и текстовое замечание по номеру страницы; координатные метки доступны на реально отрендеренном PDF. Подробности и открытые риски находятся в `docs/qa-report.md` и `docs/backlog.md`.
