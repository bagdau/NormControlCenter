# НормКонтрольЦентр

Серверное приложение для сдачи и проверки учебных работ. Студент отправляет PDF/DOCX или отчёт из формы и получает квитанцию. Преподаватель просматривает документ, публикует замечания, принимает исправленные версии и фиксирует внутреннее согласование. Администратор создаёт структуру и учётные записи, но не читает работы студентов.

Данные хранятся в PostgreSQL, загруженные файлы — в приватном Docker-томе. Приложение **не создаёт аккаунты и работы при запуске**. Без PostgreSQL сервер не стартует. Официальные оценки, ЭЦП, автоматическая проверка соответствия стандартам и интеграция с LMS не реализованы.

## Запуск на сервере

Нужны Docker Compose, домен с DNS-записью на сервер и открытые порты 80/443. Скопируйте `.env.example` в `.env` и задайте `POSTGRES_PASSWORD`, `SESSION_SECRET` и `DOMAIN`. Не коммитьте `.env`.

```sh
docker compose -f docker-compose.yml -f compose.production.yml up --build -d --wait
curl -fsS "https://$DOMAIN/api/health"
```

Первый администратор создаётся один раз на пустой базе. Используйте собственные email, имя и пароль длиной от 16 символов:

```sh
read -rsp 'Initial admin password: ' ADMIN_PASS; echo
printf '%s' "$ADMIN_PASS" | docker compose -f docker-compose.yml -f compose.production.yml exec -T app bun db/bootstrap-admin.ts admin@example.org 'Administrator Name'
unset ADMIN_PASS
```

После входа администратор добавляет факультет, кафедру, группу, преподавателя, студента и назначает преподавателя на группу. Преподаватель создаёт пространство и задание. Полная последовательность и настройки сервера описаны в [инструкции развертывания](docs/deployment.md).

## Проверка кода

```powershell
npx --yes bun install --frozen-lockfile
npx --yes bun run lint
npx --yes bun test
npx --yes bun run build
```

Изолированная проверка установки с новой БД описана в [отчёте QA](docs/qa-report.md). Контрольные записи не загружаются в рабочую БД. Копирование и восстановление данных описаны в [инструкции эксплуатации](docs/operations.md).

## Границы проверки

Чистый запуск, миграции и полный цикл через API проверены локально в Docker. Доменное HTTPS-развертывание, мобильный и планшетный полный сценарий и эксплуатация на сервере организации ещё требуют проверки там. Не называйте внутреннее согласование официальной подписью или допуском к защите.
