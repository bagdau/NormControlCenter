## Найдено и исправлено

1. Преподаватель с доступом к группе мог читать работы чужого задания: добавлены проверка владельца задания и фильтры очереди/списка.
2. PDF конструктора пересоздавался при скачивании: теперь сохраняются исходные байты и хеш квитанции проверяется по скачанному файлу.
3. Повтор ключа с иным содержимым возвращал чужую квитанцию: теперь HTTP 409; повторная сдача до опубликованного возврата запрещена.
4. Compose не собирался без Dockerfile и открывал PostgreSQL наружу: добавлен Dockerfile, конфигурация без секретов по умолчанию, порт БД закрыт, приложение привязано к localhost.
5. Просмотр загруженного файла рисовал вымышленные страницы: PDF отображается из фактических байтов; DOCX честно предлагается скачать.
6. UI мог показывать ошибку после успешной сдачи из-за сбоя обновления данных: квитанция открывается сразу из подтверждённого POST. Ложные сообщения о сохранённом черновике убраны.

## Открытые блокеры пилота

- P0: нет проверенного восстановления БД и приватных файлов из резервной копии. По условию STOP из задания реальный запуск запрещён.
- P1: bearer token возвращается в JSON и хранится в памяти страницы; нужны HttpOnly Secure cookie, CSRF-защита и ограничение попыток входа.
- P1: серверное сохранение черновика отсутствует; обновление страницы теряет незавершённую форму. Выбранный файл также теряется.
- P1: аудит для публикации пакета и согласования выполняется после изменения состояния; при ошибке аудита возможен ошибочный ответ клиенту. Требуется общая транзакция.
- P1: скачивание синтетических работ, включённых в исходный seed, невозможно из-за отсутствия байтов; сервер теперь возвращает 404, не выдаёт подменный документ.
- P1: полная планшетная и клавиатурная проверка не выполнена. Диалог квитанции и панель замечаний требуют управления фокусом.

Вывод: локальная репетиция основного потока прошла; обсуждать реальный пилот пока не рекомендуется.
